# 博客接入我们的图床

博客新增 `imgbed` 存储类型，通过 CloudFlare-ImgBed 原生 API 上传文件。文章图片、评论图片、用户头像可以分别设置默认策略，文件管理也可在图床挂载目录中上传。API Token 由博客后端使用，不写入文章链接；后台读取凭据时显示掩码。

## 发布

需要发布本次修改的博客后端和前端。当前 `.github/workflows/custom-image.yml` 在构建博客镜像时拉取前端仓库，默认引用 `custom`；发布前必须保证两边的对应修改都已进入构建引用，或手动指定包含修改的 `frontend_ref`。无需修改图床部署或 `server-ops` 配置。

这次实现不修改生产凭据、不迁移已有文件。线上渠道、HTTPS 和恢复流程仍需要部署后验收。

## 图床准备

1. 确认图床 HTTPS 地址可访问，例如 `https://img.thpvip.xyz`，并在图床后台配置好实际存储渠道。
2. 在图床后台创建给博客专用的 API Token，授予 `upload` 和 `delete` 权限。接入不需要 `list`，图床没有单独的 `read` Token 权限。由管理员在博客后台填写令牌，勿提交到代码或文章中。
3. 图床文件必须允许公开读取；保留管理员登录与上传认证。若开启 `access.whiteListMode`，需确保新上传文件也允许公开访问。
4. 如果启用防盗链，在 `access.allowedDomains` 中加入 `blog.thpvip.xyz`（域名列表以英文逗号分隔）。当前图床实现允许不带 Referer 的后端读取；检查外层 nginx/CDN 规则也允许此类请求，否则复制文件和缩略图生成会失败。
5. Docker 图床中的 `cfr2` / `R2_env` 是图床服务器本地磁盘。需要外部对象存储时选择已经配置好的 S3 兼容渠道。

## 博客后台配置

进入“存储管理”，新建类型为“我们的图床”的策略：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 图床地址 | `https://img.thpvip.xyz` | 站点地址，不带 `/upload`、`/file`、查询或用户密码 |
| API Token | 管理员填写 | 图床专用令牌，可通过后台替换；保存掩码时保留原值 |
| 图床目录 | `blog/articles` | 远端上传根目录，不能为空；避免空格、特殊字符、连续斜杠或路径穿越 |
| 应用内挂载路径 | `/imgbed/articles` | 博客虚拟文件目录，须唯一，不能挂载到 `/` |
| 上传渠道 | S3 兼容存储 | 也支持 cfr2、Telegram、Discord、Hugging Face、WebDAV；由图床保存渠道凭据 |
| 渠道名称 | 留空或实际渠道名称 | 留空时由图床选择对应类型的可用渠道 |
| 文件大小上限 | 按需设置 | 同时受图床渠道和反向代理上传限制约束 |

文章、评论、头像建议分别创建策略：

| 用途 | 图床目录 | 博客挂载路径 | 默认用途标记 |
| --- | --- | --- | --- |
| 文章图片 | `blog/articles` | `/imgbed/articles` | `article_image` |
| 评论图片 | `blog/comments` | `/imgbed/comments` | `comment_image` |
| 用户头像 | `blog/avatars` | `/imgbed/avatars` | `user_avatar` |

创建后编辑新策略并选择对应默认用途。每个标记只能属于一个策略，切换时系统会取消旧策略的同名标记。保留原策略及原文件；不要把已有文件的本地策略直接改成图床。

## 文件与备份

- 新上传文件保存在图床所选渠道，博客数据库保存远端文件 ID（`FileStorageEntity.Source`）、显示名称与目录。图床远端文件使用独立生成的名称。
- 博客内重命名、同一策略内移动和目录整理保留远端 ID，不改变已有直链。内容编辑生成新文件实体；已发布文章里的旧直链仍引用旧内容。跨存储策略移动保持既有禁止规则。
- 图床已有文件不会自动导入博客；旧本地文件不会自动迁移。远端目录不是博客虚拟子目录的镜像。
- 已有文件或实体的图床策略不能直接修改类型、站点地址或上传根目录；更换这些配置时应新建策略。Token 轮换、默认用途切换仍可操作。
- 备份博客数据库以保留文件 ID 映射，同时保留旧博客数据目录。另行备份图床数据库/索引及实际文件存储；仅备份博客 `data` 目录不会包含外部图床文件。
- 删除失败（HTTP 错误或图床返回 `success:false`）时，博客保留文件记录以便重试。当前图床版本的 S3、Discord、Hugging Face、WebDAV 删除分支忽略底层 `false` 返回值，可能误报成功；本次未修改这些图床分支。使用这些渠道时，物理文件彻底清理仍需在真实渠道验证，不能仅以 API 的成功响应判断。

## 验证

已验证博客后端测试与编译、前端测试与生产构建，以及使用真实图床源码、临时数据库、合成凭据和本地磁盘渠道的隔离 API 联调（上传、字节一致读取、匿名访问、重命名后 ID 稳定、错误 Token 拒绝、删除）。

可在博客仓库重复隔离联调，不使用生产 URL 或 Token：

```powershell
node tools/testing/imgbed-integration.mjs E:/workspace/personal/code/cloud-flare-image
```

要求已安装图床仓库的 Node 依赖和本机 Go。测试在系统临时目录运行图床副本，结束后清理临时服务、数据库与文件；失败诊断仅保存到本地 `.imgbed-fixture-diagnostics.log`，勿提交。

上线验收应分别上传文章图片、评论图片、头像和普通文件，刷新后检查公网图片与缩略图、改名/同策略移动、删除、错误 Token、接近配置上限的文件，并确认真实存储渠道已删除对象。最后验证博客与图床的备份恢复后原链接仍可访问。

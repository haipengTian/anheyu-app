# 登录可见内容

文章编辑器中的“登录可见”区块由后端控制访问。游客看到登录提示；登录用户在页面加载后通过鉴权接口获取正文。后台编辑和历史原文保持完整。

## 接口与缓存

- 公开文章详情、按 URL 查询、随机文章、列表和首页推荐统一过滤受限正文，内部调用的 `WithContent` 列表模式同样过滤。包含这类区块的文章不向游客返回 Markdown 原文和历史摘要，避免已生成的摘要再次暴露内容。
- `GET /api/articles/:id/login-required-content` 使用现有 Bearer JWT。普通登录用户可读已发布、未下架且审核通过或无需审核的文章；该接口不授予后台编辑权限。
- 鉴权响应使用 `Cache-Control: private, no-store`。页面 SSR 始终使用公开内容，登录正文仅存在于当前客户端会话，退出登录或切换文章后立即隐藏。
- 搜索写入和后台手工重建均过滤受限内容。Redis、Meilisearch 和 RSS 使用新的公开内容缓存命名空间，升级后不读取旧索引或旧摘要缓存；启动时按现有流程重建搜索索引。
- HTML 按原始区块边界过滤，避免异常表格重排漏出正文；遇到 SVG 等结构中仍残留的受限节点时，整篇显示登录提示。

本次实现针对“登录可见”。付费内容和密码保护仍需要各自的服务端授权流程。

## 发布与验收

前后端需要一起发布。只更新前端无法阻止公开接口返回原文；只更新后端会使游客保护生效，但旧前端无法加载登录正文。本次没有数据库迁移。

发布新镜像并重启应用后，如域名前有 CDN 或额外页面缓存，清除旧文章页面、公开文章接口和 RSS 缓存。发布前已经显示的内容和已泄露的凭据需要另行清理或更换。

使用一篇包含普通测试文字的文章验收：

1. 在“登录可见”区块内放置无敏感信息的标记文字，区块外保留公开文字。
2. 无痕窗口访问文章及公开详情、`by-url`、`random` 和文章列表，确认响应中没有受限标记文字；公开正文和登录入口仍可见。
3. 用普通账号登录后查看正文，再退出登录，确认受限文字立即隐藏。页面仍可通过登录入口返回原文章。
4. 搜索区块内的独有标记文字应无正文命中；后台手工重建索引后重复检查。
5. 后台再次编辑文章，确认受限原文没有被删除。遇到加载失败时页面保留登录提示，并提供“重试”。

本地检查：后端 `go test ./...`；前端 `npm test`、`npx tsc --noEmit` 和 `npm run build`。服务器上的原账号交互和实际缓存需在发布后验收。
